# Сравнение `perf stat -r 5`: baseline и fused

Каждый запуск обрабатывал тестовое изображение (22 022 007 байт) по 50 итераций. Использовался один и тот же release-бинарник; размеры чанков — значения по умолчанию: 16/64/256 KiB. В fused параметр `BLAKE3_BATCH` не задавался, поэтому применялось значение по умолчанию 64 байта. Для каждого режима `perf stat` выполнил пять повторов.

## Сравнительная таблица

| Метрика | Baseline | Fused | Разница fused к baseline |
|---|---:|---:|---:|
| Время, с (среднее ± разброс) | 2,892 ± 0,219 (±7,58%) | 1,588 ± 0,125 (±7,88%) | −45,1%; ускорение 1,82× |
| Cycles | 2 872 240 650 (±0,64%) | 2 535 810 007 (±1,37%) | −11,7% |
| Instructions | 8 185 230 881 (±0,00%) | 8 236 772 883 (±0,00%) | +0,63% |
| Cache references | 285 008 623 (±0,52%) | 278 589 859 (±0,27%) | −2,25% |
| Cache misses | 24 221 813 (±0,42%) | 14 243 814 (±1,21%) | −41,2% |

Знак минус означает меньшее значение у fused; знак плюс — большее. Проценты разброса и время приведены из вывода `perf stat` по пяти повторам.

## Краткий вывод

Число инструкций почти одинаковое: у fused примерно на 0,63% больше. При этом у fused на 41,2% меньше cache-misses и на 11,7% меньше cycles. Среднее время в этой серии ниже в 1,82 раза; относительный разброс времени около 8% для обоих режимов, поэтому точную величину ускорения по времени следует трактовать осторожно.

Таблица описывает результаты этого входного файла, этого бинарника и этих условий. Счётчики показывают сопутствующие различия, но сами по себе не доказывают, что именно снижение cache-misses вызвало ускорение.
