# Сводные результаты на ядрах Linux

Исходники Linux 3.4.5, 3.4.6 и 3.4.7: несжатый tar ≈451 MiB на ядро.
CPU 3; 5 итераций × 5 повторов perf; min/avg/max = 4096/10240/65536, batch = 8192.
Каждая ячейка — среднее арифметическое по трём ядрам, после нормирования для каждого ядра.
Дельта = (среднее fused / среднее baseline − 1) × 100%; для долей — относительное изменение.
Ускорение = отношение средних времён. Производные показатели не имеют оценённого разброса.

## Основные наблюдения

- Ускорение fused: 1,65×; время уменьшилось на 39,3%, инструкций на байт стало больше на 5,2%.
- Промахи L1 / MiB: −15,0%; L2 после L1D: −74,9%; DTLB: −77,5%; L3 всей системы: −57,5%.
- В отдельном прогоне BLAKE3 примерно в 9,5 раза меньше промахов L1 / MiB, чем при чанкировании; при чанкировании примерно в 2,9 раза меньше промахов L2 после L1D / MiB.
- На картинке при тех же chunk/batch ускорение составляло 1,83×. Изменились содержимое, размер и число итераций (50 → 5), поэтому снижение нельзя приписать только размеру входа.

## Методика и ограничения

Измеряется весь процесс, включая загрузку входа и проверку карты BLAKE3. Tar включает заголовки и заполнение.
Chunking_only сохраняет копии чанков; blake3_only хеширует срезы по готовой карте. Их времена не являются точным разложением baseline.
L3 учитывает фон всей системы. Циклы с запросами L2 в полёте не равны циклам простоя. Три близкие версии ядра не представляют разнообразный набор типов данных.
